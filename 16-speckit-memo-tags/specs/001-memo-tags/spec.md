# Feature Specification: 메모 태그

**Feature Branch**: `001-memo-tags`

**Created**: 2026-11-13

**Status**: Clarified

**Input**: User description: "메모에 태그를 붙이고, 태그로 목록을 걸러 볼 수 있게 하고 싶다. 기존 API 를 쓰는 클라이언트는 깨지면 안 된다."

## Clarifications

### Session 2026-11-13

- Q: 한 메모에 붙일 수 있는 태그 개수를 제한하는가? → A: 최대 10개. 초과하면 거부한다.
- Q: 태그 하나의 허용 길이는? (FR-008 의 "허용 길이") → A: 공백 제거 후 1~30자.
- Q: "Meeting" 과 "meeting" 은 같은 태그인가? → A: 같은 태그다. 저장하고 비교할 때 앞뒤 공백을 제거하고 소문자로 정규화한다.
- Q: 이미 만든 메모의 태그 수정을 이번 범위에 포함하는가? → A: 포함하지 않는다. 별도 기능으로 다룬다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 메모를 만들 때 태그를 붙인다 (Priority: P1)

메모 작성자가 메모를 만들면서 "회의", "아이디어" 같은 태그를 함께 지정한다. 저장된 메모를 조회하면 붙인 태그가 보인다.

**Why this priority**: 태그가 저장되지 않으면 이후 기능(필터링)이 성립하지 않는다. 이것만 구현해도 "분류 가능한 메모"라는 최소한의 가치가 생긴다.

**Independent Test**: 태그 2개를 포함한 메모를 생성하고, 같은 메모를 조회했을 때 두 태그가 그대로 돌아오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 태그가 없는 상태, **When** 제목과 태그 ["회의", "아이디어"] 로 메모를 만들면, **Then** 메모가 생성되고 응답과 이후 조회에 두 태그가 포함된다.
2. **Given** 태그 없이 메모를 만드는 기존 클라이언트, **When** 기존과 같은 요청을 보내면, **Then** 이전과 똑같이 성공하고 태그는 빈 목록으로 조회된다.
3. **Given** 같은 태그가 중복된 요청 ["회의", "회의"], **When** 메모를 만들면, **Then** 태그는 한 번만 저장된다.

---

### User Story 2 - 태그로 목록을 걸러 본다 (Priority: P2)

메모 사용자가 특정 태그를 지정해서 그 태그가 붙은 메모만 목록으로 본다.

**Why this priority**: 태그를 붙이는 목적이 "나중에 골라 보기"이므로 가치의 핵심이지만, 저장(P1)이 먼저 있어야 한다.

**Independent Test**: 태그가 다른 메모 세 개를 만들어 두고, 한 태그로 필터했을 때 해당 메모만 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** "회의" 태그 메모 2개와 태그 없는 메모 1개, **When** 태그 "회의"로 목록을 조회하면, **Then** "회의" 메모 2개만 돌아온다.
2. **Given** 태그 필터를 지정하지 않은 요청, **When** 목록을 조회하면, **Then** 이전과 똑같이 모든 메모가 돌아온다.
3. **Given** 어떤 메모에도 없는 태그, **When** 그 태그로 조회하면, **Then** 오류가 아니라 빈 목록이 돌아온다.

---

### User Story 3 - 사용 중인 태그 목록을 본다 (Priority: P3)

사용자가 지금까지 쓴 태그의 목록(과 각 태그가 붙은 메모 수)을 한 번에 본다.

**Why this priority**: 편의 기능이다. 필터(P2)는 사용자가 태그 이름을 알고 있어야 쓸 수 있어서, 이 목록이 있으면 발견하기 쉬워지지만 없어도 핵심 가치는 유지된다.

**Independent Test**: 서로 다른 태그를 가진 메모를 만든 뒤 태그 목록을 조회하고, 태그 이름과 개수가 맞는지 확인한다.

**Acceptance Scenarios**:

1. **Given** "회의" 2개, "아이디어" 1개가 붙은 메모들, **When** 태그 목록을 조회하면, **Then** 각 태그와 메모 수가 돌아온다.
2. **Given** 메모가 하나도 없는 상태, **When** 태그 목록을 조회하면, **Then** 빈 목록이 돌아온다.

---

### Edge Cases

- 태그 이름이 빈 문자열이거나 공백뿐이면 어떻게 되는가?
- 태그 이름이 너무 길면 어떻게 되는가?
- 한 메모에 태그를 매우 많이 붙이면 어떻게 되는가?
- 태그를 지정해서 조회할 때 태그 이름의 앞뒤 공백이나 대소문자가 다르면 어떻게 되는가?
- 메모를 삭제하면 그 메모에만 붙어 있던 태그는 태그 목록에서 사라지는가?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 메모를 만들 때 0개 이상의 태그를 함께 받을 수 있어야 한다.
- **FR-002**: 시스템은 메모를 조회할 때 그 메모에 붙은 태그를 항상 포함해서 돌려줘야 한다. 태그가 없으면 빈 목록이고, 태그는 **이름순으로 정렬**해서 돌려준다.
- **FR-003**: 태그를 지정하지 않고 만든 메모와, 태그 관련 입력이 없는 기존 요청은 이전과 같은 결과로 처리되어야 한다.
- **FR-004**: 한 메모에 같은 태그가 중복 지정되면 한 번만 저장해야 한다.
- **FR-005**: 시스템은 태그 하나를 지정해서 그 태그가 붙은 메모만 목록으로 돌려줄 수 있어야 한다. 지정하지 않으면 전체 목록이다.
- **FR-006**: 존재하지 않는 태그로 조회하면 빈 목록을 돌려줘야 하며 오류가 아니다.
- **FR-007**: 시스템은 사용 중인 태그와 각 태그가 붙은 메모 수의 목록을 돌려줄 수 있어야 한다.
- **FR-008**: 빈 태그, 공백뿐인 태그, 30자를 넘는 태그는 거부하고, 어느 입력이 문제인지 알려주는 오류를 돌려줘야 한다. 태그로 조회할 때 지정하는 값에도 같은 규칙을 적용한다.
- **FR-009**: 시스템은 한 메모에 붙일 수 있는 태그를 최대 10개로 제한하고, 초과하면 거부하면서 한도를 알려줘야 한다.
- **FR-010**: 시스템은 태그를 저장하고 비교할 때 앞뒤 공백을 제거하고 소문자로 정규화해야 한다. ("Meeting" 과 "meeting" 은 같은 태그다.)
- **FR-011**: 이미 만든 메모의 태그 수정은 이번 범위가 아니다. (별도 기능으로 다룬다.)

### Key Entities *(include if feature involves data)*

- **메모(Memo)**: 제목, 내용, 생성 시각을 가진 기존 항목. 이번 기능으로 0개 이상의 태그를 가진다.
- **태그(Tag)**: 메모를 분류하는 짧은 이름. 독립된 관리 대상이 아니라 메모에 붙는 값이며, 같은 이름은 여러 메모에 붙을 수 있다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 태그를 지정해 만든 메모를 조회하면 100% 지정한 태그가 그대로 돌아온다.
- **SC-002**: 태그를 쓰지 않는 기존 요청은 변경 전과 변경 후의 응답이 필드 추가를 제외하고 동일하다 (기존 자동화 테스트 100% 통과).
- **SC-003**: 태그로 조회한 결과에는 그 태그가 없는 메모가 하나도 포함되지 않는다.
- **SC-004**: 잘못된 태그 입력은 모두 거부되며, 거부 응답에서 문제가 된 입력이 무엇인지 확인할 수 있다.

## Assumptions

- 태그 기능의 사용자는 기존 메모 API 의 사용자와 같다. 인증과 권한은 이번 범위가 아니다.
- 태그는 메모에 붙는 단순한 이름이며, 색상이나 계층(하위 태그) 같은 속성은 이번 범위가 아니다.
- 메모 하나에 여러 태그를 붙일 수 있고, 한 번의 조회에서 필터하는 태그는 하나다. (여러 태그 동시 필터는 이번 범위가 아니다.)
- 이미 저장된 메모는 태그가 없는 상태로 그대로 유효하다.
- 요청의 `tags` 배열에 숫자처럼 문자열이 아닌 값이 있으면 JSON 변환 규칙에 따라 문자열로 바뀌어 저장될 수 있다. (엄격한 형식 검사는 이번 범위가 아니다. converge G3)
